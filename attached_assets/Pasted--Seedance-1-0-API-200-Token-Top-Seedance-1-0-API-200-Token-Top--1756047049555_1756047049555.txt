Viewing and managing model inference
Log in to ModelArk and click Online inference in the left navigation bar to go to the list page. The list page displays the name, status, create time, and admin information for each endpoint. You can perform actions including API call, trial, stop, and delete.
Image

On the Online inference page, you can search by endpoint name, model name, and endpoint id.
The following table describes the statuses of inference endpoints.
Parameter

Description

Endpoint status

Scheduling: The backend resource is being scheduled. It may be in a queue or has been started.

Healthy: The endpoint is in normal status and can be called properly.

This parameter does not indicate the endpoint load. If the rate limit is exceeded, the status may still be healthy, but the service will return an error.

Stopped: The user stops the access.

Abnormal: The connected model is abnormal. You can submit a work order for handling at the backend.


Viewing inference endpoint details
Click the name of an inference endpoint to access its details page, where you can view the overview, monitoring, API calls, and other information of the endpoint.

Overview
You can view the model information of the endpoint.

Basic information: connected model, rate limits, creator, and other information.
Billing information: billing type and input/output price.
Associated agents.
Click ··· in the upper right corner to edit information or delete the service. Note that you can change the model version but not the base model.
Check whether the rate limits of the endpoint meet your needs in the specific scenarios. If not, you can follow the front-end instructions to submit a work order to customer service.

API calls
This page displays the two authorization methods for API calls.
Method 1: API key After creating an API key on ModelArk, use the API key to obtain the service call permission of the corresponding endpoint.
You can obtain the API key on the API key management page, configure environment variables, and refer to the sample API to call the endpoint.
ImageMethod 2: Authorize by BytePlus IAM. After permissions are granted for subaccounts on IAM, the access key and secret access key in the API access of the subaccount can be used for resource-level authentication, which is more secure and controllable.
After obtaining authorization, you can use the multilingual SDK provided by the platform to initiate calls after configuring the access key and secret access key in environment variables.
Image


Monitoring configuration
This page displays the tokens per minute (TPM), API latency, error rate, streaming first frame latency, streaming non-first token latency, and non-streaming latency. To view monitoring data, you need to perform three steps: Enable the VMP service, authorize cross-service access, and select a workspace.
Image

1. Activate the VMP service and create a workspace
VMP: BytePlus managed services for Prometheus

Click Activate in step 1 to go to the VMP activation application page. Read and confirm the service overview and billing method, and then click Apply for activation. After the service is activated, click View product details to enter the VMP configuration page.
Note
You need VMPFullAccess to complete this configuration. You can configure the permission through IAM in the upper right corner of the console.
If you purchase a standard VMP workspace, you will not be charged for the monitoring metrics collected by ModelArk. For VMP billing details, see Billing Details.


2. Authorize cross-service access
Cross-service access requires activation of the VMP service. If this service has been activated in step 1, cross-service access will be authorized automatically.

3. Select the workspace
Associate the workspace configured in step 1 with the endpoint. After you click Save, the Monitoring tab appears.
Image

Metric alerting configuration

Prerequisites
For detailed instructions on BytePlus authorization, see https://docs.byteplus.com/en/docs/byteplus-platform/docs-what-is-the-policy-syntax .

If alert rules need to be configured for a subaccount, the VMPFullAccess permission of the account is required. If you only have VMPReadOnlyAccess, the following API permissions need to be added:

VMP: CreateAlertingRuleGroup, which creates alert rule groups via an alert template.
VMP: UpdateAlertingRuleGroup, which updates alert rule groups.
VMP: UpgradeAlertingRuleGroups, which upgrades alert rule groups based on the latest alert template.
VMP: DeleteAlertingRuleGroup, which deletes alert rule groups.

Creating an alert rule group
Click Configure metric alert in the upper right corner of the Monitoring tab to go to the alert configuration page.

For Template category, select ARK. You can view predefined alert templates. If existing alert templates do not meet your needs, you can configure your own template based on the VMP Creating an alert rule. Then, click Next to go to the basic information page.
Basic information includes the alert name, associated workspace, applicable endpoint IDs, notification policy, and aggregation policy. After the configuration is completed, click Next to configure the alert rule.
Configuration has been set based on the selected template. You can make adjustments as needed. Then, click OK.
Configured alert rules can be edited or deleted.

Alert notification
Notifications can be sent via email or SMS. For more information, see Alert Center.

Monitoring
This page displays the TPM, API latency, error rate, first token latency, non-first token latency, token input length, and token output length.
