# 客戶小鎮 × AI 創意工坊：串接交接說明

這份文件是給客戶小鎮的工程師（與他們的 AI 助手）看的。目的：讓客戶小鎮的後端能呼叫 AI 創意工坊的生成 API，並把兩邊需要對齊的事一次列清楚。

完整的端點規格、欄位與範例在同一個資料夾的 `partner-api.md`，請把那份一起提供。這份只講分工、流程、要對齊的資料與待確認事項。

## 一、分工

| 誰 | 負責 |
|---|---|
| AI 創意工坊 | 圖片、影片、寫真套圖、AI 角色的生成；檔案保存在 CDN；扣積分與退積分；內容安全 |
| 客戶小鎮 | 自己的使用者與工作區、畫面與操作流程、呼叫 API、保存結果網址、排程發文到社群、向自己的客戶收費 |

AI 創意工坊不認識客戶小鎮的使用者。兩邊唯一的對應是 `owner_ref`（工作區代號）與 `external_ref`（你們自己的單號）。

## 二、連線方式

- 只能從**後端**呼叫。帶 `Origin` 標頭的瀏覽器請求會被拒絕（403）。
- 網址前綴：`https://<AI 創意工坊的網域>/api/v1/partner`
- 驗證：`Authorization: Bearer <權杖>`。權杖由 AI 創意工坊管理員在後台建立，全文只顯示一次。
- 所有工作區共用**一個服務帳號**與一個積分餘額。
- 生成都是非同步：建立後拿到 `job_id`，再查詢結果。目前**沒有 webhook**，要用輪詢。
- 錯誤一律是 `{ "error": "中文說明", "code": "英文代碼" }`。請用 `code` 判斷，`error` 可以直接顯示給使用者。

## 三、可以用的功能

| 功能 | 端點 | 費用（積分） |
|---|---|---|
| 查價目與可用選項 | `GET /pricing` | 0 |
| 查餘額 | `GET /balance` | 0 |
| 上傳照片 | `POST /uploads` | 0 |
| 建立／查詢／修改／刪除 AI 角色 | `/characters` | 0 |
| 角色四視圖 | `POST /characters/:id/four-views` | 20 |
| 生成圖片 | `POST /images` | 每張 6（無浮水印）或 5（有浮水印） |
| 生成影片 | `POST /videos` | 每秒 8（720p）或 15（1080p） |
| 寫真套圖 | `POST /photosets` | 每張 6 或 5 |
| 查任務結果 | `GET /jobs/:id` | 0 |

價格以 `GET /pricing` 的回傳為準，請不要寫死在程式裡。

## 四、建議的串接流程

**A. 建立 AI 角色（每個工作區做一次）**

1. 使用者在客戶小鎮上傳 3 張以上照片 → 每張呼叫 `POST /uploads`（帶 `owner_ref`）→ 拿到網址。
2. 向使用者確認「照片中的人是本人或已取得本人同意」→ 呼叫 `POST /characters`，帶 `consent: true`。
3. （建議）呼叫 `POST /characters/:id/four-views` 產生四視圖，之後生成的一致性會更好。
4. 把回傳的角色 `id` 存在你們的資料庫，對應到工作區。

**B. 生成**

1. 呼叫 `POST /images`、`/videos` 或 `/photosets`，帶 `owner_ref`、`character_ids`、`external_ref`，並加上 `Idempotency-Key` 標頭。
2. 收到 `202` 與 `job_id` → 存起來。
3. 每 3–5 秒查一次 `GET /jobs/:id?owner_ref=...`，直到 `status` 是 `succeeded` 或 `failed`。圖片約 1–3 分鐘，影片約 2–10 分鐘。
4. `succeeded`：`results[].url` 是永久網址，可直接使用或另存。
5. `failed`：把 `error` 顯示給使用者；積分已自動退回（`credits_refunded`）。

## 五、一定要遵守的規則

1. **每個角色端點、每個帶角色的生成都要帶 `owner_ref`。** 帶錯會得到 404，內容和「不存在」完全一樣。
2. `owner_ref` 請用穩定、不會重複使用的代號：1–100 個英數或符號字元，不可有空白或中文。工作區改名時代號不能變。
3. 建立角色必須有 `consent: true`，而且要真的問過使用者。AI 創意工坊會記錄同意時間。
4. 使用角色生成時不能帶 `nsfw: true`（會回 400）。
5. 建立類的請求都帶 `Idempotency-Key`（例如「貼文代號＋用途」）。逾時重送同一個 key 不會重複扣點。
6. 向你們的客戶計費時，以 `credits_charged − credits_refunded` 為準，並等任務結束再結算。
7. 收到 `429` 時依 `Retry-After` 的秒數等待再試，不要立刻重送。
8. 權杖只放在後端的機密設定，不要進前端或版本庫。

## 六、要對齊的資料

請客戶小鎮提供：

| 項目 | 用途 |
|---|---|
| `owner_ref` 的實際格式與範例 | 確認符合字元限制 |
| 預估用量：每天幾張圖、幾支影片、尖峰時每分鐘幾個請求 | 設定權杖的頻率與每日上限，以及預存多少積分 |
| 每個工作區大約幾個角色 | 目前上限是每個 `owner_ref` 50 個 |
| 會用到哪些尺寸與比例 | 確認在 `/pricing` 的清單內 |
| 測試環境與正式環境是否分開 | 是的話會發兩把權杖、綁兩個帳號 |
| 技術聯絡人 | 權杖交付、異常通知 |
| 肖像下架的聯絡窗口 | 收到本人要求時通知誰 |

AI 創意工坊會提供：

| 項目 | 說明 |
|---|---|
| 正式網域 | API 的網址 |
| 服務權杖 | 透過安全管道單獨交付，不放在文件或聊天紀錄裡 |
| `partner-api.md` | 完整規格與範例 |
| 權杖的限制 | 每分鐘請求數、每日圖片與影片上限 |
| 服務帳號的積分餘額與補充方式 | 餘額不足會回 402 |

## 七、兩邊要一起決定的事

1. **積分不足時怎麼辦。** 所有工作區共用一個餘額，用完全部停擺。客戶小鎮要不要在餘額低於某個數字時通知？誰負責補？
2. **各工作區的用量怎麼算。** AI 創意工坊只記總帳。要分工作區統計，請客戶小鎮自己用 `owner_ref` 與任務回傳的 `credits_charged` 累計。
3. **浮水印。** 預設不加（每張 6 積分）。要不要改成加浮水印（5 積分）？
4. **使用者刪除帳號或工作區時。** 客戶小鎮需要逐一呼叫 `DELETE /characters/:id`，角色的照片與四視圖才會從 CDN 刪除。已經生成的成品不會被刪。
5. **肖像下架。** AI 創意工坊管理員可以停用單一角色或整個工作區的角色。停用後生成會回 `403 character_disabled`，客戶小鎮的畫面要怎麼顯示？
6. **內容被拒。** 提示詞或圖片未通過安全審查時任務會失敗（`code: content_rejected`）並退點，客戶小鎮要給使用者什麼提示？
7. **要不要 webhook。** 目前只有輪詢。如果用量大到輪詢成為負擔，可以再加。

## 八、目前的限制

- 影片一次只能帶一個角色，而且必須是圖生影片（模型只接受一張首幀）。文字生影片不能帶角色。
- 圖片與寫真套圖一次最多帶 3 個角色；參考圖合計最多 10 張（套圖 9 張）。
- 上傳單檔 10 MB，只接受 JPG、PNG、WEBP，短邊至少 256 像素；每個 `owner_ref` 每分鐘 30 次。
- 角色參考圖 3–30 張。
- 沒有「列出所有任務」的端點，請自己保存 `job_id`。
- 建立角色不支援 `Idempotency-Key`，重送會建立第二個角色；請在自己這邊避免重複送出。

## 九、建議的驗收步驟

請用測試權杖依序確認：

1. `GET /balance`、`GET /pricing` 正常回應。
2. 上傳 3 張照片 → 建立角色 → 查得到。
3. 用另一個 `owner_ref` 查同一個角色 → 404。
4. 做四視圖 → 輪詢到 `succeeded` → 角色的 `four_view_urls` 有 4 張。
5. 用角色生成一張圖 → 輪詢到 `succeeded` → 網址打得開。
6. 同一個 `Idempotency-Key` 送兩次 → 回同一個 `job_id`，只扣一次。
7. 故意送錯（少 `consent`、帶錯 `owner_ref`、積分不足）→ 得到文件寫的錯誤代碼，且沒有扣點。
8. 刪除角色 → 查不到，也不能再用來生成。

## 十、給 AI 助手的提示

如果你是協助客戶小鎮工程師實作的 AI：

- 以 `partner-api.md` 的欄位名稱與範例為準，不要猜欄位。文件沒寫的行為請列為待確認，不要自行假設。
- 實作一個集中的 API 用戶端：統一加上驗證標頭、`Idempotency-Key`、逾時、`429` 退避，並把錯誤的 `code` 轉成你們自己的例外類別。
- 輪詢請做成背景工作，不要卡住使用者的請求。任務狀態（`job_id`、`owner_ref`、`external_ref`、狀態、結果網址、扣點與退點）要存進資料庫。
- 每一次呼叫都從目前的工作區取得 `owner_ref`，不要讓前端傳入。
- 不要把權杖寫進程式碼、日誌或錯誤訊息。
